# ADR-0004 — HTTP : hyper/axum au serveur, hyper-util vers l'amont

- **Statut :** accepté
- **Date :** 3 novembre 2026
- **Contexte :** cahier des charges §6.3, T0.6.

## Contexte

Le serveur doit parler HTTP/1.1 et HTTP/2, streamer des réponses SSE sans les réassembler, et
nous devons contrôler finement le pool de connexions amont, les timeouts et la pression arrière.

## Décision

- **Serveur :** `hyper` 1.x + `axum` (routage, extracteurs, couches `tower`).
- **Client amont :** `hyper-util` avec pool HTTP/2 et `rustls`, pour garder la main sur les
  quatre timeouts (connexion, premier octet, inter-morceaux, total).
- `reqwest` reste une dépendance **de test uniquement** (tests d'intégration du simulateur).

## Alternatives écartées

- **actix-web** : modèle d'acteurs inutile ici, contrôle du pool amont moins direct.
- **warp** : surface d'API plus étroite pour les couches et l'observabilité.
- **reqwest en production** : pratique, mais moins de contrôle sur le pool, les timeouts fins et
  le streaming `Bytes` sans copie.

## Conséquences

- Les couches `tower` (limite de corps, timeout d'en-têtes, limite de connexions) sont posées en
  T1.1.
- HTTP/2 multiplexé vers chaque fournisseur, pool préchauffé au démarrage.
- `rustls` avec accélération matérielle (AES-NI, ARMv8 Crypto) comme backend TLS.
- La version d'axum est centralisée dans `[workspace.dependencies]`.
