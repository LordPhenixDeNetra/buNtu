# ADR-0006 — Interface web : SvelteKit statique embarquée

- **Statut :** accepté **sous réserve** du prototype de validation (annexe C du cahier)
- **Date :** 3 novembre 2026
- **Contexte :** cahier des charges §6.3 et FR-UI-6, T0.6.

## Contexte

L'interface d'administration doit être embarquée dans le binaire, légère (< 1 Mo gzip), bilingue
FR/EN, et ne doit exiger aucun Node au runtime.

## Décision

**SvelteKit en mode statique** (`adapter-static`), TypeScript strict, client d'API **généré**
depuis `openapi.json` (`openapi-typescript`), i18n FR/EN dès le départ, thème clair/sombre, et
embarquement des fichiers compilés via `rust-embed` (cache long sur les fichiers hachés).

## Alternatives écartées

- **Next.js** : plus lourd, serveur Node ou export statique moins direct.
- **Leptos / UI en Rust** : séduisant (un seul langage) mais écosystème UI plus jeune.
  **Cette alternative n'est pas définitivement écartée** : l'annexe C du cahier impose un
  prototype d'une journée avant de trancher. Si le prototype invalide SvelteKit, un nouvel ADR
  remplace celui-ci.
- **Bibliothèque de composants lourde** : refusée sans accord explicite.

## Conséquences

- Node n'est requis qu'au **build** ; la CI construit et mesure l'UI (poids gzip < 1 Mo).
- Aucune chaîne visible en dur : tout passe par l'i18n FR/EN.
- CSP stricte, HSTS, `frame-ancestors 'none'` ; cookies `HttpOnly` + `SameSite=Strict`.
